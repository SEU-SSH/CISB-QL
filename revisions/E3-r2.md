## Changes

- Query-originated non-monotonic recursion may include library locations without
  terminating repair. Every external error must be in pinned cpp-all and share
  an explicit, complete query-defined symbol with a local recursion cycle.
  Timeouts, dependency failures and unrelated/unknown errors remain infrastructure errors.
- MCP now offers position-independent `codeql_search_api(query, offset=0)` over
  fixed local `.qll` source, with ten bounded source excerpts per page.
- Completion filters the entire LSP-returned collection before twenty-item
  pagination. Model payloads keep full documentation but omit editor fields;
  native MCP receipts remain available. Identical pages reference earlier calls.
- All four tools share six admitted calls per generation attempt. No hidden
  searches, extra candidates, model file-write tools, history pruning or LSP reuse.
- Runtime metadata records E3-r2, tool schemas/bounds, the fixed library root,
  and all deployed MCP JavaScript hashes, including the new helper.

## Reproducibility and Limits

`e3-r2-freeze.sha256` and `runs/e3-r2-validation/source.tar.gz` record this
implementation separately. The manifest covers harness sources, config, specs,
pack inputs, tests, docs, deployment patch/lock and MCP source/runtime files.
Old manifests, archives and experiment receipts are retained unchanged.

Search is lexical, includes experimental/internal APIs, and may require paging
or narrower terms. It does not establish public availability, inheritance,
receiver compatibility or correct use in a generated query. Completion retains
LSP incompleteness rather than claiming a complete API index.

These checks establish working mechanisms, not improved model compilation rate,
lower token cost or semantic correctness. Future live-model testing requires a
separate disclosed experimental freeze; old and revised batches must not be pooled.

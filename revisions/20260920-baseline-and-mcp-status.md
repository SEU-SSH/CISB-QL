## 无 MCP 时保留什么

off 关闭的是 MCP/LSP 会话及搜索、hover、definition、completion，不关闭 CLI 编译和修复。现有 Python 环境仍保留 `mcp` 依赖，不在本次拆包或调整部署。

当前基线路径为：spec 校验 -> Responses 生成 -> 双文件格式检查 -> CLI `--check-only` -> 按剩余预算修复 -> 保存结果 -> 可选 smoke。

| 保留能力 | 当前行为与依据 |
|---|---|
| 输入和输出检查 | spec 必需字段/类型、重复 ID/JSON 字段检查；只接受两个非空代码字段。`spec_io.py:13`、`harness.py:39` |
| 格式与 QL 修复 | 首次加最多三次修复；格式错误占用同一预算，不编译不完整候选。`harness.py:152` |
| 环境预检 | 检查固定 CLI、pack/lockfile，先编译手写模板再消耗模型请求。`codeql_tools.py:272`、`codeql_tools.py:386` |
| 错误分类 | 查询错误才修复；缺包、超时等基础设施故障不让模型改代码。E3-r2 递归分类修正同样作用于 off。`codeql_tools.py:299` |
| 可追溯记录 | 每轮候选、请求/响应、原始诊断、usage 和耗时；失败也留存。`harness.py:221`、`run.py:89` |
| 独立复验与汇总 | 可选 C/C++ smoke；`--smoke-from` 不调用模型；`report.py` 对明确配对的 A/B 结果汇总，不自动筛选最好结果。`run.py:153`、`report.py:139` |

这些增强不等于“首次引入编译修复”。旧项目保留的 `/home/suiren/cisb-llm/agents/querier.py:294` 已有双文件生成、编译及默认三次修复；新的增量主要是格式修复、错误分类、预检、记录和复验能力。旧 Querier 使用完整 `query compile`，当前主循环使用 `--check-only`，不能称所有检查都更强。参照范围是保留的旧实现，不是一次新旧受控实验。

本轮 A 是当前 Harness off，不是旧 Querier，因此 A 的 5/5 不能证明重构后优于旧实现。实际命令示例见 README，继续使用现有五个 spec、配置和输出隔离规则，不回写旧项目查询。
